# API Автотесты для Restful-booker

[![API Autotests](https://github.com/Curzxced/X5_API_DEMO_TESTS/actions/workflows/api-tests.yml/badge.svg)](https://github.com/Curzxced/X5_API_DEMO_TESTS/actions/workflows/api-tests.yml)

Это демонстрационный проект по автоматизации тестирования REST API. 
Я подготовил этот фреймворк, чтобы показать свои навыки, системный подход и умение работать с современными инструментами (включая ИИшку).

В качестве тестового стенда был выбран тренировочный сервис [Restful-booker](https://restful-booker.herokuapp.com), так как он предоставляет полный CRUD-цикл, требует авторизации и позволяет проверить обработку негативных сценариев.

---

## Стек технологий
*   **Язык:** Python 3.15 (локально) / Python 3.14 (Docker и CI).
*   **Фреймворк:** Pytest (фикстуры, параметризация, маркеры).
*   **HTTP-клиент:** Requests (с переиспользованием `Session` для оптимизации запросов).
*   **Инфраструктура:** Docker и Docker Compose (для запуска в изолированной среде).
*   **CI/CD:** GitHub Actions (автозапуск тестов при пуше).

---

## Архитектура проекта

Я вынес логику в отдельные слои, чтобы проект было легко поддерживать и масштабировать:

```example_api_test_for_X5
├── api/
│   └── client.py          # Слой API-клиента (инкапсуляция методов HTTP)
├── tests/
│   ├── conftest.py        # Фикстуры (настройка сессии, авторизация, генерация данных)
│   ├── test_auth.py       # Тесты авторизации (смоук)
│   └── test_booking.py    # Тесты CRUD и негативные сценарии (регрессия)
├── config.py              # Конфигурация (URL, креды)
├── pytest.ini             # Настройки Pytest и кастомные маркеры
├── Dockerfile             # Сборка контейнера
└── docker-compose.yml     # Упрощенный запуск
```
## Инструкция по запуску

Предварительные требования: Python 3.14+ и Docker Desktop.

Локальный запуск:
1. Установить зависимости: pip install -r requirements.txt
2. Запустить тесты: pytest
(Опционально: pytest -m smoke для быстрых тестов, pytest -m regression для полного прогона)

Запуск в Docker:
1. Собрать образ: docker build -t api-tests .
2. Запустить тесты: docker run --rm api-tests

## Использование ИИ

Проект написан с использованием ИИ, с ручной доработкой и отладкой.

Что делал ИИ:
- Генерация базового каркаса класса BookingClient (методы GET/POST/PUT/DELETE).
- Составление шаблона yaml-файла для GitHub Actions.
- Черновой вариант Dockerfile на базе python:3.14-slim.

Что делалось руками:
- Исправление логики авторизации: ИИ предлагал передавать токен в заголовке Authorization, но после проверки документации метод был переписан на передачу токена через Cookie.
- Дописывание методов __enter__ и __exit__ для корректной работы контекстного менеджера (with) в фикстурах pytest.
- Проектирование изоляции тестов: написана фикстура created_booking с использованием yield для удаления тестовых данных после каждого теста.
- Тест-дизайн: ручное добавление негативных сценариев и параметризации через pytest.mark.parametrize.
- Отладка окружения: решение проблем с импортами в Docker.
